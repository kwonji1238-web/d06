# /api-check — API 화면 규칙 검사기 (강사용 예시 답안)

너는 **검사만 하는 사람**이야. 이 화면을 만든 대화는 못 봤고, 알 필요도 없어. 파일과 규칙만 보고 판단해. 파일은 절대 고치지 않아.

## 검사 대상

- `$ARGUMENTS`에 적힌 HTML 파일. 비어 있으면 현재 폴더의 `.html` 파일 전부.
- 기준: `.claude/rules/api.md`와, 같은 폴더(없으면 위 폴더)의 `CLAUDE.md`. 규칙 본문은 `CLAUDE.md`에, 이유와 `## 실수에서 배운 규칙`은 `api.md`에 있다. 둘 다 읽는다.

## 순서

1. 두 파일을 읽고 규칙을 한 줄씩 목록으로 만든다.
2. HTML 파일을 읽고, 규칙마다 지켰는지 **코드에서 근거(줄 번호)** 를 찾는다.
3. 규칙에 빠져 있어도 아래 4가지는 반드시 본다. 내용은 `CLAUDE.md`의 "d6-api 화면 구조"를 기준으로 한다.
   - ① `// 🔌` 표시 (주소 한 곳 모음, `fetch` 줄 표시)
   - ② API 상자 (실제 부른 주소, "새 탭에서 원본 JSON 보기" 링크)
   - ③ 실패 화면 (`fetch`마다 실패 처리와 안내 문구, 카드별 따로 호출)
   - ④ 출처·기준 날짜 (근거 없는 "실시간" 금지)
4. 주소에 `key=`, `apikey=`, `token=`, `YOUR_API_KEY`가 보이면 표 가장 위에 **위험**으로 적는다.

## 보고 형식

고치지 말고 아래 표로만 보고한다. 규칙마다 한 행씩 쓴다.

| 규칙 | 결과 | 근거 (줄) | 사람이 직접 확인할 것 |
| --- | --- | --- | --- |
| ⚠️ 키 노출 | 위험 / 없음 | 줄 번호 | 주소에 key=, token= 검색 |
| ① 🔌 표시 | 지킴 / 안 지킴 / 모름 | 12, 40 | Ctrl+F로 `🔌` 검색 |
| ② API 상자 | 지킴 / 안 지킴 / 모름 | 줄 번호 | 화면 맨 아래 상자와 링크 클릭 |
| ③ 실패 화면 | 지킴 / 안 지킴 / 모름 | 줄 번호 | 인터넷을 끄거나 주소를 틀리게 해서 열어 보기 |
| ④ 출처·기준 날짜 | 지킴 / 안 지킴 / 모름 | 줄 번호 | 화면에 출처·날짜·"실시간" 표현 확인 |
| (나머지 규칙) | 지킴 / 안 지킴 / 모름 | 줄 번호 | 규칙에 맞게 |

- 코드만으로 판단할 수 없으면 "모름"으로 적고, 사람이 확인할 방법을 마지막 칸에 쓴다.
- 표 아래에 "안 지킴"과 "위험" 항목만 한두 줄로 요약한다.
