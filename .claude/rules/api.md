## API 화면 규칙
- 규칙 본문(키 없는 공개 API만, 🔌 주석, API 상자, 로딩·실패 화면, 출처·기준 날짜, 단일 HTML, 커밋 금지)은 `CLAUDE.md`의 "d6-api 화면 구조"와 "작업 규칙"을 따른다. 여기에는 CLAUDE.md에 없는 이유와 세부 문구만 둔다.
- 출처 문구: Open-Meteo는 "Weather data by Open-Meteo.com"으로 적는다. (왜: API 규칙이 출처 표기를 요청함)
- 이유 모음
  - 키 금지: HTML은 누구나 코드를 볼 수 있어서 키가 새어 나감
  - 🔌 한 곳 모음: 어디가 API인지 바로 찾으려고
  - API 상자: 주소를 바꾸면 주문이 바뀌는 걸 눈으로 보려고
  - 카드별 실패 처리: 무료 API는 멈추거나 바뀜
  - 기준 날짜: 환율은 하루 한 번 발표되는 기준값
  - 단일 HTML: 설치 없이 바로 확인하려고
  - 커밋 금지: 세이브 포인트는 내가 검사한 뒤에 찍음
- API 값이 없거나(빈 응답, 필요한 필드 없음) API가 응답하지 않으면, 화면에 "사용 오류"와 이유(예: HTTP 오류, 값 없음)를 그대로 보여 준다. 가짜·예시·임의로 만든 데이터로 화면을 채우거나 다른 API로 몰래 바꾸지 않는다. (왜: 없는 데이터를 있는 것처럼 보여 주면 거짓 정보가 되고, 어디가 고장 났는지 알 수 없음) → 검사: `fetch` 실패·빈 응답 분기에서 하드코딩된 대체 데이터나 더미 목록을 쓰지 않나

## 추가
- 환율을 "실시간"이라고 씀 / 기준 날짜를 빼먹음
- 실패 화면 없이 `fetch`만 씀 → 주소가 틀리면 하얀 화면

- 키가 필요한 날씨 API(OpenWeatherMap 등)를 골라 와서 `YOUR_API_KEY` 자리를 남김 → 규칙 첫 줄 위반
- Nager.Date 공휴일 이름을 영어(`name`)로만 보여 줌 → 한국어는 `localName`
